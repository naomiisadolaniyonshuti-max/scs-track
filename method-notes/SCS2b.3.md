1. **What we set out to do:** Launch our first EC2 instance from a launch sheet, verify security group inbound rules, observe the IP address change across a stop/start, diagnose a fault card, and end the lab cleanly.
2. **What we actually did:** Launched the EC2 micro instance, tested port reachability before and after adding the HTTP inbound rule, logged every step with expected vs actual output in `cloud/instance-log.md`, recorded the pre- and post-stop public IPs, and ended the lab.
3. **What we checked, and what it showed:** Checked the class server prompt beside the live web page, inbound security group rules, and outside port knocks; showed that traffic stays blocked until the security group permits port 80 and that stopping an instance releases its ephemeral public IP.
4. **How long it took, against the plan:** Took about 3 hours across the taught lab, SGL logging, partner port checks, and cleanup, matching the scheduled session blocks.
5. **One lesson for the next person:** Always verify both the OS service (listening on the port) and the cloud security group inbound rules before troubleshooting a refused connection, and always End Lab when finished.
6. **What I might be wrong about, and how I would find out:** I assumed the public IP only changes on a full stop/start rather than a reboot; I would verify that by running a reboot test in a sandbox lab and comparing `curl ifconfig.me` before and after.
